# FFCL benchmark

Every number below is produced by the programs in `src/` and `scripts/`, and the tables are a pure function of the two result files (`bin/results/ffcl.json`, `bin/results/reference.json`). Re-run with `./ffcl_benchmark all` and `python3 scripts/benchmark_reference.py`, then `python3 scripts/make_tables.py`.

The result files and the datasets are generated and therefore not versioned - `benchmark/bin/` is ignored. This file is the record of the run described below, regenerated from those files by `scripts/make_tables.py`; the numbers will not match exactly on another machine.

This file is the single-dimension (2-D) FFCL-vs-Python/FLANN run. The multi-dimension, all-library matrix — pico_tree, ArborX, mlpack, pdbscan, pargeo, nanoflann, FLANN, sklearn, scipy and hdbscan at 2-, 3- and 4-D, 1 and 6 threads — is in [references/README.md](references/README.md).

## How to read this

- **Machine**: Intel(R) Core(TM) i5-9600KF CPU @ 3.70GHz, 6 cores, no SMT.
- **Threads**: every measurement is single threaded (`threads: 1`).
- **Timing policy**: each workload runs **3 times**; every cell is `mean / median` in seconds.
- **Datasets**: 10 000 samples each, generated by `scripts/MakeClusteringDatasets.py` (2 features, the usual sklearn clustering toy sets plus `iris`/`mnist`).
- **Leaf size**: one value per library, never tuned per dataset. FFCL uses `sqrt(n)/3` (≈33 at n = 10 000), every reference uses **40**, which is the default of both `sklearn.neighbors.KDTree` and `hdbscan`. Both are the generally good values for their library.
- **Apple to apple**: identical datasets, identical parameters, identical per-query workload (1 000 query points against the full dataset, k = 2), exhaustive/idle threads on both sides, and both sides include the core-distance computation in the MST row.

## Known discrepancies

One behaviour found while writing the unit tests, recorded here rather than hidden:

1. **Single-cluster silhouette is NaN.** `silhouette()` divides by zero when there is only one cluster. It cannot be asserted in a unit test because the library is built with `-Ofast`, which implies `-ffinite-math-only` and makes `std::isnan()` a constant `false`.

## Reproducing

```sh
python3 benchmark/scripts/MakeClusteringDatasets.py          # -> bin/datasets/
cmake -B build_bench -DMODE=benchmark -DCMAKE_BUILD_TYPE=Release
cmake --build build_bench -j
./build_bench/ffcl_benchmark all                            # -> bin/results/ffcl.json
python3 benchmark/scripts/benchmark_reference.py            # -> bin/results/reference.json
python3 benchmark/scripts/make_tables.py                    # -> benchmark/README.md
```
